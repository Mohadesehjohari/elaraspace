# بازیابی ارسال و دریافت درخواست‌ها (۱۸ اکتبر ۲۰۲۶)

## چه چیزی در کد تعمیر شد؟

- راه‌اندازی درخواست دوستی، دعوت همکاری و اتصال حساب مستقل است: خطای یک ماژول بقیه را از کار نمی‌اندازد.
- درخواست‌های دوستی مستقیماً از `friendRequests` دریافت می‌شوند؛ شکست در دریافت آمار، فعالیت، بی‌صداکردن یا پروفایل غیرعمومی باعث ناپدیدشدن درخواست نمی‌شود.
- لینک دوحسابی در `accountLinks` رویداد لحظه‌ای ورودی، اعلان درون‌برنامه‌ای، شمارنده، بازخوانی دستی، بازخوانی بعد از آنلاین‌شدن و نمایش خطای مجوز دارد.
- `collabInvites` اگر اجازهٔ خواندن نداشته باشد، خطای مرتبط در صفحه درخواست‌ها نمایان می‌شود.
- تسک‌ها فقط اگر «مشترک» انتخاب شده باشند به حساب متصل ارسال می‌شوند؛ «فقط برای من» مانع ارسال آینده است.
- دکمهٔ «↻ دریافت دوبارهٔ درخواست‌ها» در صفحهٔ دوستان هر سه صندوق درخواست را واکشی می‌کند.

## ضروری برای فعال‌شدن روی Firebase واقعی

**تغییر `firestore.rules` در GitHub به معنی انتشار قوانین در Firebase نیست.** اگر پروژهٔ `elara-ab1aa` هنوز قوانین جدید را ندارد، درخواست‌های اتصال و دعوت مشترک ممکن است با `permission-denied` رد شوند.

با حساب دارای مجوز Firebase در پروژه `elara-ab1aa`:

1. از قوانین فعلی `Firestore Database → Rules` بکاپ بگیرید و مطمئن شوید سرویس‌های دیگری به آن وابسته نیستند.
2. تفاوت‌ها را بررسی و `firestore.rules` شاخهٔ `main` را با Rules پروژه هماهنگ کنید.
3. در Firebase Console دکمهٔ **Publish** را بزنید، یا پس از ورود با Firebase CLI از ریشهٔ مخزن اجرا کنید:

```sh
firebase deploy --only firestore:rules --project elara-ab1aa
```

4. نسخهٔ جدید سایت را از ریپوی `Mohadesehjohari/elaraspace` منتشر کنید. برای GitHub Pages انتشار شاخهٔ `main` را بررسی کنید؛ اگر دامنهٔ سفارشی از cPanel عرضه می‌شود، `Deploy HEAD Commit` را اجرا کنید. هیچ‌کدام از این استقرارها صرفاً با ویرایش قوانین محلی انجام نمی‌شوند.
5. هر دو حساب باید **ورود کرده و ایمیل‌شان تأیید شده باشد**. برای اعلان درون‌برنامه‌ای، دوست باید سایت را باز کند یا دوباره وارد شود؛ این نسخه اعلانات Push دستگاه در حالت بسته‌بودن سایت ندارد.

## تست واقعیِ دو کاربر

در دو مرورگر مستقل با حساب A و B:

1. از بخش دوستان درخواست دوستی A→B را ارسال کنید؛ در صندوق B، درخواست دریافتی را ببینید و قبول کنید.
2. از A به B درخواست **اتصال حساب** بفرستید؛ در صفحهٔ دوستان B باید «درخواست اتصال حساب» با دکمه‌های قبول/رد و اعلان درون‌برنامه‌ای ظاهر شود.
3. پس از قبول، کنار B در حساب A و کنار A در حساب B وضعیت «حساب‌ها متصل‌اند» دیده شود.
4. در A یک تسک آزمایشی خصوصی ثبت کنید و مطمئن شوید به B نرفته؛ همان تسک را مشترک کنید و در B دعوت/نسخهٔ اشتراکی را بررسی کنید.
5. در B دکمهٔ «دریافت دوبارهٔ درخواست‌ها» را بزنید. اگر خطای Firebase وجود دارد، متن خطا در کارت مربوط نشان داده می‌شود.
6. تست قطع اتصال و ارسال بعد از قطع را انجام دهید؛ موارد قبلاً کپی‌شده با قطع اتصال خودکار حذف نمی‌شوند.

## آزمون خودکار کد (بدون دسترسی به Firebase واقعی)

```sh
node tests/account-link-visibility.test.cjs
node tests/request-delivery-regression.cjs
```

تست Firestore با Emulator، پس از راه‌اندازی Emulator:

```sh
cd tests
npm run rules:test
```

اگر `permission-denied` نمایش داده شد، ابتدا **قوانین واقعاً منتشرشده در Firebase** را بررسی کنید؛ تنظیمات `.firebaserc` و فایل‌های مخزن به‌تنهایی ثابت نمی‌کنند قوانین روی سرویس فعال‌اند.
