# راهنمای اتصال Gemini به GitHub Pages الارا (Cloudflare Workers)

**وضعیت:** کد اتصال در ریپو قرار گرفته است. برای فعال‌شدن AI باید Worker را در حساب خودت بسازی و آدرس آن را به سایت بدهی. این روش نیازی به خرید cPanel ندارد؛ محدودیت‌ها و هزینه احتمالی Google/Cloudflare جدا هستند.

## مرحله ۱ — ساخت سرویس

1. وارد https://dash.cloudflare.com شو و یک حساب بساز.
2. در Workers & Pages، گزینه Create Worker را انتخاب کن؛ نامی مثل elara-ai-gateway مناسب است.
3. کد فایل cloudflare/elara-ai-worker.js از همین ریپو را در Worker قرار بده و Deploy کن.
4. از بخش Workers KV یک namespace به نام دلخواه مثل ELARA_AI_STATE بساز.
5. در تنظیمات Worker، یک KV namespace Binding ایجاد کن:
   - Variable name باید دقیقاً AI_CONFIG باشد.
   - Namespace همان ELARA_AI_STATE باشد.
6. در تنظیمات Worker، قسمت Variables and Secrets یک Secret به نام AI_MASTER_KEY اضافه کن. مقدار باید ۶۴ کاراکتر تصادفی هگزادسیمال (۳۲ بایت) باشد؛ مثلاً خروجی دستور زیر را فقط در دستگاه خودت بساز:

       openssl rand -hex 32

   این مقدار محرمانه است. آن را در GitHub یا اسکرین‌شات قرار نده. یک بکاپ امن از آن نگه‌دار؛ گم‌کردن آن باعث می‌شود کلیدهای Gemini قبلی قابل بازیابی نباشند.

## مرحله ۲ — اتصال GitHub Pages

1. آدرس HTTPS نهایی Worker را از Cloudflare کپی کن. شکل آن شبیه https://elara-ai-gateway.YOUR-SUBDOMAIN.workers.dev است.
2. در GitHub فایل ai-gateway-config.js را باز کن و مقدار ELARA_AI_API_URL را با آدرس Worker تنظیم کن. فقط آدرس عمومی را وارد کن، **نه کلید Gemini**.
3. Commit را در شاخه main ثبت کن و صبر کن GitHub Pages آپدیت شود.
4. داشبورد https://mohadesehjohari.github.io/elaraspace/admin/ را دوباره بارگذاری کن.

## مرحله ۳ — ثبت کلید Gemini

1. وارد Elara Admin → هوش مصنوعی شو.
2. در Tokenها و مدیریت بار، یک نام مستعار غیرشخصی مثل Primary و یک Gemini API Key تازه را وارد کن؛ اولویت 10 و سقف روزانه 0.
3. یک مدل با Technical Model ID معتبر ثبت یا ویرایش کن؛ Worker در حالت اولیه gemini-2.5-flash را پیشنهاد می‌کند. شناسه‌های مدل در https://ai.google.dev/gemini-api/docs/models هستند.
4. در تنظیمات AI گزینه فعال را روشن کن، مدل پیش‌فرض را تعیین کن و ذخیره کن.
5. تست اتصال مدل پیش‌فرض را بزن، بعد در صفحه Elara AI یک پیام واقعی بفرست.

**اگر API Key را قبلاً در اسکرین‌شات یا جای عمومی نشان دادی، کلید قدیمی را در Google AI Studio لغو کن و کلید جدید بساز.**

## خطاهای متداول

- پیام عدم وجود backend روی GitHub Pages: آدرس Worker هنوز داخل ai-gateway-config.js تنظیم نشده یا تغییر در GitHub Pages منتشر نشده است.
- خطای AI_CONFIG: Binding ذخیره‌سازی KV به Worker اضافه نشده.
- خطای AI_MASTER_KEY: Secret با نام یا قالب درست ثبت نشده.
- خطای Origin: Worker فقط دامنه https://mohadesehjohari.github.io را قبول می‌کند؛ برای دامنه سفارشی باید همان Origin را در ALLOWED_ORIGINS اضافه و دوباره Deploy کنی.
- خطای Admin: سند Firestore مسیر admins/{uid} باید enabled=true و role برابر owner یا admin داشته باشد و ایمیل مدیر تأیید شده باشد.
- HTTP 404 در تست: Technical Model ID را مطابق مدل‌های واقعی مجاز حساب خودت بررسی کن.

## حریم خصوصی و حدود فنی

- GitHub Pages خودش PHP ندارد. وقتی ELARA_AI_API_URL خالی باشد، مسیر PHP قبلی برای هاست cPanel حفظ شده است.
- Firebase ID token در بک‌اند بررسی می‌شود؛ کلید Gemini در Cloudflare KV به صورت AES-256-GCM نگهداری و هرگز به مرورگر برگردانده نمی‌شود.
- متن درخواست‌ها برای پاسخ‌گرفتن به Google Gemini ارسال می‌شود. شرایط حریم خصوصی Google AI Studio را بررسی کن.
- حافظهٔ ابری به‌صورت پیش‌فرض **خاموش** است. کاربر پس از ورود باید گزینه «حافظه شخصی الارا» را در چت روشن کند. روشن‌کردن، آخرین گفتگوهای محلی همان حساب را به فضای رمزگذاری‌شده Cloudflare KV منتقل می‌کند.
- اگر حافظه روشن باشد، حداکثر ۶۰ پیام اخیر روی سرور در رکورد رمزگذاری‌شده جداگانه برای هر Firebase UID نگه‌داری می‌شود؛ پاسخ‌گویی Gemini فقط ۱۲ پیام اخیر را به‌عنوان بافت مکالمه دریافت می‌کند.
- وقتی حدود ۱۰ پیامِ هنوز خلاصه‌نشده جمع شود، Worker پیش از حذف تدریجی پیام‌های قدیمی از بافت ۱۲پیامی، با یک درخواست اضافه به Gemini خلاصه‌ای از ۸ پیام قدیمی‌تر می‌سازد. خلاصه حداکثر ۱۸۰۰ نویسه دارد و در درخواست‌های بعدی (حتی از دستگاه دیگر) به عنوان حافظه زمینه‌ای استفاده می‌شود. خلاصه‌سازی ممکن است هزینه/سهمیهٔ اضافه مصرف کند.
- این خلاصه‌سازی فقط در حالت فعال‌بودن حافظه کاربر انجام می‌شود؛ همیشه بی‌نقص نیست و در صورت خطای Gemini یا Cloudflare ممکن است انجام نشود. بهتر است کاربر اطلاعات واقعاً حیاتی را جداگانه در یادداشت ماندگار وارد کند.
- از بخش «خلاصه خودکار گفتگوهای قبلی»، خود کاربر می‌تواند خلاصه را ببیند و به تنهایی پاک کند. پاک‌کردن «گفتگوهای اخیر» هم خلاصه خودکار را پاک می‌کند، اما یادداشت‌های دستی را نگه می‌دارد.
- هر کاربر می‌تواند تا ۲۵ یادداشت مهم (حداکثر ۳۵۰ نویسه) را با گزینه «به خاطر بسپار» ثبت کند. این یادداشت‌ها حتی بعد از طولانی‌شدن مکالمه در پاسخ‌های بعدی استفاده می‌شوند. حافظه خودکار و نامحدودِ همه حرف‌ها در این نسخه وجود ندارد.
- پاک‌کردن گفتگو تاریخچه ابری را پاک می‌کند اما یادداشت‌های صریح را نگه می‌دارد؛ خاموش‌کردن یا حذف کامل حافظه رکورد ابری شامل گفتگو و یادداشت‌ها را پاک می‌کند.
- بدون فعال‌کردن حافظه، گفتگو فقط در مرورگر همان دستگاه نگهداری می‌شود. دسترسی سروری به یادداشت‌ها با Firebase Auth کنترل می‌شود و محتوای رکورد با همان Secret امن Worker رمزگذاری می‌شود.
- **انتشار کد حافظه روی GitHub، Worker فعال Cloudflare را به‌روزرسانی نمی‌کند**. برای فعال‌شدن حافظه باید محتوای آخرین فایل cloudflare/elara-ai-worker.js را دوباره در Workers & Pages → elara-ai-gateway → Edit code جایگزین و Deploy کنی؛ Binding و Secret قبلی را تغییر نده.

- سهمیه‌های روزانه در Workers KV تقریبی و غیراتمیک هستند و برای کنترل مالی سخت‌گیرانه کافی نیستند؛ برای مصرف بالا باید شمارنده اتمیک و محدودیت‌های هزینه در Google Cloud تنظیم شود.

## دستیار اجرایی تسک‌ها (نسخه اولیه)

این قابلیت مخصوص صفحه **آزادی → Elara AI** است و به ذخیره اصلی تسک‌ها در حساب Firebase کاربر متصل می‌شود.

1. دستور را در کادر Elara AI بنویس، مانند «برای فردا ساعت ۹ تسک مطالعه آلمانی بساز».
2. به جای «ارسال پیام»، روی **اجرای دستور تسک** بزن.
3. Gemini یک پیشنهاد ساختاریافته می‌دهد (ساخت، نمایش، ویرایش، تکمیل یا حذف).
4. الارا نام و جزئیات تسک را برای تأیید نشان می‌دهد؛ بدون تأیید کاربر **هیچ تغییری اعمال نمی‌شود**.
5. تغییر تأییدشده با همان قالب تسک اصلی در دستگاه ثبت و توسط زیرساخت معمول Firebase سایت همگام‌سازی می‌شود.

**محدودیت‌ها:** این نسخه فقط تسک‌های شخصی را پوشش می‌دهد، نه تسک‌های اشتراکی یا مرتبط با بخش‌های دیگر. تغییر تسک‌های تکرارشونده را با رابط اصلی انجام بده. تشخیص عنوان، تاریخ و ساعت ممکن است دقیق نباشد؛ پیش‌نمایش را پیش از تأیید بخوان. نتیجه «ثبت در سایت» به معنی موفقیت قطعی سینک روی همه دستگاه‌ها نیست؛ در صورت خطای Firebase وضعیت Cloud Sync را بررسی کن.

**انتشار الزامی Worker:** چون Worker به‌صورت دستی ساخته شده، تغییر فایل GitHub به‌تنهایی کافی نیست. یک بار **جدیدترین نسخه** cloudflare/elara-ai-worker.js را کپی کن و در Cloudflare → Workers & Pages → elara-ai-gateway → Edit code جایگزین کن و Deploy بزن. کلیدهای Gemini، AI_CONFIG و AI_MASTER_KEY را دست نزن.

**حریم خصوصی:** برای تفسیر فرمان، متن دستور و فهرست محدودی از عنوان/تاریخ/شناسه تسک‌ها به Google Gemini API ارسال می‌شود. خود Worker هرگز تسکی را در حساب Firebase ایجاد یا حذف نمی‌کند. کنترل نهایی با کاربرِ واردشده است.


## ذخیره‌سازی حساب در حافظه موقت صفحه — حالت آزمایشی (Server-only beta)

**این حالت هنوز برای همهٔ کاربران فعال نشده است.** برای آزمایش آدرس زیر را هنگام ورود به سایت باز کن:

\`https://mohadesehjohari.github.io/elaraspace/?serverOnly=1#home\`

- در این حالت، نسخهٔ اصلی تسک‌ها، هدف‌ها، عادت‌ها و بخش‌های وابسته از \`private/{uid}/app/main\` در **Firestore** خوانده می‌شود.
- برای حفظ سازگاری ماژول‌های فعلی، کلید \`elara_space_v1\` در همان تب مرورگر و فقط در RAM شبیه‌سازی می‌شود؛ **نسخه جدید این کلید در localStorage نوشته نمی‌شود**.
- سابقهٔ جدید چت Elara AI در این حالت هم در RAM نگهداری می‌شود؛ اگر حافظه شخصی ابری فعال باشد، تاریخچه مجاز با رمزگذاری در Cloudflare ذخیره می‌شود.
- بازگشت به آدرس معمولی (بدون \`?serverOnly=1\`) رفتار قدیمی را برمی‌گرداند. نسخه‌های **قدیمی و بکاپ محلی** به‌دلیل احتمال داشتن تغییرات ذخیره‌نشده خودکار پاک نمی‌شوند.
- هنگام ذخیره‌سازی در Firebase، وضعیت «در حال ذخیره…» و سپس «✓ ذخیره شد» را کنترل کن. اگر اتصال قطع باشد یا پیش از ذخیره تب را ببندی، داده‌ای که فقط در RAM مانده ممکن است از بین برود. تا پایان تست، از این حالت برای اطلاعات حیاتی استفاده نکن.
- Firebase Authentication و کلیدهای دیگری مثل ترجیحات و اعلان‌ها هنوز ممکن است از فضای مرورگر استفاده کنند. بنابراین این بتا **حذف کامل تمام داده‌های محلی کل سایت** نیست؛ فقط اولین گام برای دادهٔ اصلی حساب و چت جدید است.
- پیشنهاد آزمایش: با یک حساب تست، یک تسک و یک هدف آزمایشی بساز، منتظر «✓ ذخیره شد» بمان، در تب دیگر همان آدرس آزمایشی را باز کن و بررسی کن هر دو داده از Firestore ظاهر می‌شوند؛ سپس خروج و ورود مجدد و تفکیک از حساب دوم را بررسی کن.
- پیش از حذف داده‌های قدیمی مرورگر، از داده‌ها **بکاپ** بگیر و مطمئن شو تغییرات روی سرور هستند. حذف خودکار یا پاک‌کردن تمام سایت در این مرحله توصیه نمی‌شود.


## انتقال کنترل‌شدهٔ داده‌های ۴ حساب به Firebase

**واقعیت معماری:** داده‌های اصلی کاربران ثبت‌نام‌شده از قبل در مسیر
`private/{uid}/app/main` روی Firebase Firestore بارگذاری و ذخیره می‌شوند؛
`localStorage` تا پیش از حالت آزمایشی «serverOnly» نقش کپی/وضعیت محلی هم داشته است.
Cloudflare KV حافظهٔ جداگانهٔ AI است و مقصد ذخیرهٔ تسک‌ها و هدف‌ها نیست.

برای هر کدام از چهار کاربر، یک‌بار با **همان حساب و همان مرورگر/دستگاهی که اطلاعات قدیمی در آن بوده** وارد شوید:

1. در منوی حساب (سه خط یا عکس پروفایل)، **تنظیمات → انتقال اطلاعات و بکاپ** را انتخاب کنید.
2. تعداد تسک‌ها، اهداف و عادت‌های روی Firebase و فهرست «موارد جاافتاده» را بررسی کنید.
3. روی «دانلود بکاپ ابری» بزنید. اگر نسخه قدیمی یافت شد، نسخه قدیمی دستگاه را نیز دانلود و در جایی امن نگهداری کنید.
4. اگر موارد جاافتاده وجود داشت، منبع صحیح را انتخاب کنید، تأیید کنید که داده‌های محلی **متعلق به همین حساب** هستند، و سپس «انتقال موارد جاافتاده» را بزنید.
5. صبر کنید پیام «انتقال و خواندن مجدد Firebase تأیید شد» نمایش داده شود؛ بعد در مرورگر/دستگاه دیگر همان حساب را بررسی کنید.
6. پس از تأیید، فقط به‌صورت آزمایشی از آدرس `?serverOnly=1` استفاده کنید تا دادهٔ اصلی در RAM بماند و ذخیرهٔ دائمی محلی جدید برای کلید اصلی ایجاد نشود.

مهاجرت **تنها رکوردهای دارای شناسه یا نام جدید را اضافه می‌کند**. رکوردهای هم‌نام/هم‌شناسهٔ موجود در Firebase دست‌نخورده می‌مانند و رکوردهای مشترک یا مدیریت‌شده به‌صورت خودکار وارد نمی‌شوند. هیچ اطلاعاتی از یک دستگاه بدون تأیید صاحب حساب به حساب دیگری منتقل نمی‌شود. حافظهٔ AI نیز جداگانه و اختیاری است و فعال‌کردن/ورود به حساب کاربری باعث واردشدن خودکار چت خصوصیِ کاربران دیگر نمی‌شود.

**موارد مهم:** این مسیر ادعای «انتقال کامل خودکار همهٔ داده‌های هر مرورگر» ندارد؛ داده‌های محلی ممکن است متعلق به حساب دیگر باشند یا قبلاً پاک شده باشند. مرحله بازیابی در سایت زنده هنوز باید با یک حساب آزمایشی تست شود. کپی‌های محلی قدیمی خودکار حذف نمی‌شوند. JSON بکاپ شامل اطلاعات شخصی است، پس آن را در جای امن نگهداری کنید و در چت یا GitHub عمومی قرار ندهید.


## الارا، دستیار اجرایی چندبخشی (۲۰ اکتبر ۲۰۲۶)

نسخه جدید در صفحه «آزادی → Elara AI» یک دکمه با عنوان **«اجرای دستور در سایت»** دارد. این دکمه از مسیر جدید **POST /ai/action-plan** روی Cloudflare Worker استفاده می‌کند.

نمونه دستورهای تک‌مرحله‌ای:
- «برای فردا ساعت ۹ یک تسک مطالعه بساز.»
- «هدف یادگیری آلمانی تا آخر آذر با سه ریزقدم بساز.»
- «عنوان هدف زبان رو به آلمانی B1 تغییر بده.»
- «ریزقدم گوش‌دادن رو به هدف آلمانی اضافه کن.»
- «عادت پیاده‌روی روزهای شنبه و دوشنبه بساز.»
- «عادت مطالعه رو حذف کن.»
- «هدف‌های من رو نشون بده.»
- «تسک مطالعه رو انجام‌شده بزن.»

**حوزه نسخه اول:** ایجاد، ویرایش، حذف و نمایش تسک‌ها، اهداف، عادت‌ها و ریزقدم‌های اهداف. تکمیل دستی تسک/عادت ساده و ریزقدم ساده هم پشتیبانی می‌شود. یک دستور در هر درخواست؛ وقتی مورد مبهم باشد الارا درخواست توضیح می‌کند. تغییر ساعت عادت و مدیریت نوبت‌های تکرارشونده پیچیده در این نسخه قابل اجرا نیست؛ از فرم معمولی سایت استفاده کن.

**ایمنی:** Gemini فقط پیشنهاد ساختاریافته ارائه می‌کند؛ نه Firebase را ویرایش می‌کند و نه تسک یا هدفی را مستقیم ثبت می‌کند. مرورگر شناسه دقیق مورد و وضعیت ورود و دسترسی را دوباره بررسی می‌کند و خلاصه دستور را **قبل از اعمال** به کاربر نشان می‌دهد. بدون تأیید، هیچ تغییر جدیدی ثبت نمی‌شود. هیچ دستور دستیار حق تغییر رکورد اشتراکی یا مرتبط با سیستم‌های دیگر را ندارد. با حذف هدف، ریزقدم‌های همان هدف هم حذف می‌شوند؛ بنابراین هشدار حذف باید قبل از تأیید خوانده شود. فهرست موارد شخصیِ قابل جست‌وجو محدود است و شناسه ساختگی رد می‌شود.

**حریم خصوصی:** متن دستور و نام/شناسه/چند ویژگی محدودِ موارد شخصیِ قابل مدیریت برای تفسیر به Google Gemini ارسال می‌شود. موارد اشتراکی از فهرست ارسالی حذف شده‌اند. همهٔ داده‌های اصلی با همان مسیر قبلی حساب Firebase همگام می‌شوند؛ در حالت عادی نسخه محلی مرورگر همچنان وجود دارد و برای آزمایش حالت RAM از \`?serverOnly=1\` استفاده می‌شود.

**انتشار ضروری:** تغییرهای GitHub Pages بعد از Build سایت ظاهر می‌شوند، اما Worker در Cloudflare دستی است. برای فعال‌شدن مسیر جدید باید فایل کامل \`cloudflare/elara-ai-worker.js\` از شاخه main را دوباره جایگزین کنی و **Deploy** بزنی. Secret با نام \`AI_MASTER_KEY\` و binding با نام \`AI_CONFIG\` را تغییر نده. اگر Deploy نشده باشد، دکمه فرمان خطای 404/«مسیر پیدا نشد» می‌دهد؛ هیچ حذف یا تغییری به حساب تحمیل نمی‌شود.

**آزمایش پیشنهادی:** ابتدا روی حساب خودت هدف آزمایشی همراه با یک ریزقدم بساز؛ از پیش‌نمایش تأیید کن، بعد منتظر وضعیت «✓ ذخیره شد» بمان و از دستگاه دوم همان حساب را بررسی کن. بعد ویرایش و حذف همان مورد **آزمایشی** را امتحان کن. تست‌های خودکار API و کد مرورگر در GitHub Actions اجرا می‌شوند؛ موفقیت آن‌ها جایگزین آزمایش واقعی با حساب کاربر نیست.
