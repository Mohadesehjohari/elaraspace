# بکاپ یکجای Firebase الارا — بدون کارت بانکی

این برنامه فقط روی کامپیوتر مالک پروژه اجرا می‌شود. هیچ کلید مدیریتی، پسورد یا داده‌ای را به ChatGPT یا GitHub ارسال نمی‌کند. با Firebase Admin SDK **فقط می‌خواند** و داده‌های Firestore و مشخصات حساب‌های Firebase Authentication را به یک فایل **رمزگذاری‌شده با AES-256-GCM** تبدیل می‌کند. قبل از ذخیره خروجی، برنامه صحت رمزگشایی را کنترل می‌کند.

**توجه:** این روش «Export رسمی Firestore» نیست و از سهمیه خواندن عادی پایگاه داده استفاده می‌کند. سقف رایگان به مصرف فعلی پروژه بستگی دارد. این ابزار نمی‌تواند مواردی را که فقط در مرورگر یک نفر باقی مانده‌اند بازیابی کند. حافظه هوش مصنوعی Cloudflare و فایل‌های Google Cloud Storage نیز جدا هستند. ابزار حاضر هیچ چیزی را از Firebase حذف یا در آن ایجاد نمی‌کند.

## اجرای ساده روی ویندوز

1. **Node.js LTS** را از https://nodejs.org دانلود و نصب کن.
2. **سورس همین پروژه** را از https://github.com/Mohadesehjohari/elaraspace/archive/refs/heads/main.zip دانلود و از حالت ZIP خارج کن.
3. در https://console.firebase.google.com/project/elara-ab1aa/settings/serviceaccounts وارد **Service accounts** شو. فقط اگر به این پروژه دسترسی مالک داری، روی **Generate new private key** و تأیید کلیک کن تا فایل JSON ویژهٔ این پروژه دانلود شود. این فایل **کلید بسیار حساس مدیریت Firebase** است؛ آن را عمومی نکن و برای هیچ شخص یا چتی نفرست.
4. پوشه پروژه را باز کن و به \`tools\admin-backup\` برو. فایل JSON مدیریت را **بکش و روی فایل \`backup-windows.cmd\` رها کن** (Drag & Drop). برای بار اول نصب کتابخانه‌ها به اینترنت نیاز دارد.
5. داخل پنجره فرمان یک رمز **جدید حداقل ۱۲ کاراکتر** انتخاب کن و دوباره وارد کن. هنگام تایپ، حروف نمایش داده نمی‌شوند. این رمز با رمز ورود سایت فرق داشته باشد.
6. برنامه تعداد اسناد Firestore و حساب‌های Firebase Authentication را نشان می‌دهد. بعد از نمایش **SUCCESS**، فایل رمزگذاری‌شده در **Downloads\Elara-Backups** یا در پوشه خانه سیستم ایجاد می‌شود. فایل و رمز را جدا از یکدیگر در جای امن نگه دار.

تا زمانی که بکاپ و رمز را در جای امن نگه نداشته‌ای، هیچ داده یا کلید محلی را پاک نکن. می‌توانی بعد از اتمام کار، کلید Service Account دانلودشده را از **IAM & Admin → Service Accounts → Keys** غیرفعال/حذف کنی؛ حذف خودسرانه کلید پیش‌فرض فعال در سایر سرویس‌ها ممکن است مشکل ایجاد کند.

## اجرای ترمینالی (اگر Node و دسترسی مدیریتی از قبل آماده‌اند)

\`\`\`sh
cd tools/admin-backup
npm install --no-fund --no-audit --ignore-scripts
node backup.mjs "/secure/path/to/firebase-adminsdk-key.json"
\`\`\`

اگر برنامه در محیط امن گوگل با Application Default Credentials با **مجوزهای مناسب Firestore و Firebase Authentication** اجرا شود، مسیر کلید را می‌توان حذف کرد. این راه ممکن است بدون حساب سرویس و مجوز درست کار نکند.

## محدوده و بازیابی

- تمام **collection**های ریشه Firestore، اسناد داخل آن‌ها و تمام subcollectionهای nested
- metadata حساب‌های Firebase Authentication؛ **بدون hash رمز عبور و passwordSalt**
- ذخیره اطلاعات با نام مسیر اصلی سند و نشانگر نوع مقادیر Firestore (timestamp, geopoint, reference, bytes)
- فایل رمزگذاری‌شده \`.json.enc\` از نظر رمزگشایی و یکپارچگی بررسی می‌شود.

**از این فایل نمی‌توان مستقیم روی دکمه Import گوگل کلیک کرد.** برای بازگرداندن اطلاعات نیاز به برنامه بازیابی اختصاصی و اجرای جداگانه با بررسی صاحب پروژه است. در این مرحله بازیابی را عمداً خودکار نکرده‌ایم تا اطلاعات فعلی چهار نفر ناخواسته بازنویسی نشود.

**مهم:** «بکاپ موفق» فقط وقتی واقعاً تأیید شده که برنامه روی دستگاهت **SUCCESS** چاپ کند و فایل خروجی را دریافت کرده باشی. صرف قرارگرفتن این کد در ریپو، بکاپ‌گرفتن از اطلاعات واقعی نیست.


## بررسی بکاپ موجود، بدون گرفتن بکاپ دوباره

اگر فایل \`elara-firebase-all-users-...json.enc\` قبلاً در Downloads/Elara-Backups ساخته شده است:

1. آخرین ZIP پروژه را از https://github.com/Mohadesehjohari/elaraspace/archive/refs/heads/main.zip دانلود و باز کن (نسخه تازه شامل فایل verify-windows.cmd است).
2. به \`elaraspace-main/tools/admin-backup/\` برو و فایل \`verify-windows.cmd\` را پیدا کن.
3. **فایل بکاپ با پسوند .json.enc** را از Downloads/Elara-Backups با ماوس روی \`verify-windows.cmd\` بکش و رها کن. **کلید خصوصی Firebase JSON را نکش.**
4. رمز **قبلی بکاپ** را وارد کن؛ برنامه آن را فقط روی همین دستگاه بررسی می‌کند.
5. پیام SUCCESS و چهار عدد «Firestore documents / Firebase Authentication accounts / Accounts with main cloud data / Matched registered accounts» را بخوان.

این کار بدون اتصال به Firebase و بدون تغییر یا آپلود داده‌ها انجام می‌شود. اصل فایل .enc رمزگذاری‌شده باقی می‌ماند و محتویات حساب‌ها در پنجره چاپ نمی‌شوند. اگر چهار حساب داده ابری داشته باشند، \`Accounts with main cloud data\` باید دست‌کم ۴ باشد؛ تعداد Firebase Authentication حساب‌ها ممکن است بیشتر یا کمتر از تعداد کاربران فعال سایت باشد. اگر کمتر از ۴ بود، پیش از هر پاک‌سازی داده‌ها باید علت بررسی شود.

بعد از تأیید، یک **نسخه دوم از فایل .json.enc** در حافظه USB امن یا فضای خصوصی رمزگذاری‌شده نگهداری کن؛ رمز فایل را در محلی جداگانه و مطمئن ذخیره کن. هرگز کلید مدیریت Firebase یا فایل .enc را داخل GitHub یا چت عمومی قرار نده.
